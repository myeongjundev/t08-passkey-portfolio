## 배포 설정값

### Supabase

프로젝트 ref: `znatzjmlhznpdqsqipab` · 리전: Northeast Asia (Seoul) `ap-northeast-2`

**Session pooler**를 씁니다. Direct connection은 IPv6 전용이라 Vercel에서 못 붙고,
Transaction pooler(6543)는 Hibernate prepared statement와 충돌합니다.

```
host      aws-0-ap-northeast-2.pooler.supabase.com
port      5432
database  postgres
user      postgres.znatzjmlhznpdqsqipab
```

**Data API는 꺼져 있습니다. 켜지 마세요.** 켜면 `private_items` 테이블이 REST로
노출돼서 T08-C16(패스키 없이 비공개 자료 요청 시 거절)에 우회로가 생깁니다.

### Vercel 환경변수 (Production)

`PORT`를 지운 뒤 **8개**가 남아야 합니다.

```
SPRING_PROFILES_ACTIVE=prod
SPRING_DATASOURCE_URL=jdbc:postgresql://aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres?sslmode=require
SPRING_DATASOURCE_USERNAME=postgres.znatzjmlhznpdqsqipab
SPRING_DATASOURCE_PASSWORD=(Supabase 프로젝트 생성 시 저장한 비밀번호)
DB_POOL_MAX=3
JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75.0
T08_WEBAUTHN_RP_ID=t08-passkey-portfolio.vercel.app
T08_WEBAUTHN_ORIGIN=https://t08-passkey-portfolio.vercel.app
```

- URL은 `postgresql://`이 아니라 **`jdbc:postgresql://`** 로 시작합니다.
- `T08_WEBAUTHN_RP_ID`는 호스트명만. `https://` 없음, 경로 없음.
- `T08_WEBAUTHN_ORIGIN`은 `https://` 포함, **끝 슬래시 없음.**
- 비밀번호는 저장소에 없습니다. 개인 보관처에서 가져오세요.

production 도메인은 `t08-passkey-portfolio.vercel.app`으로 확정됐고, 위 두 값과
일치합니다.

## 배포 디버깅 기록 (같은 함정 다시 밟지 않기)

Vercel 컨테이너 기동에서 세 번 막혔습니다. 전부 수정·검증·푸시 완료입니다.

| # | 증상 | 원인 | 수정 |
| --- | --- | --- | --- |
| 1 | `exec: "java": executable file not found in $PATH` | Vercel이 자기 환경변수로 컨테이너를 실행해서 베이스 이미지의 `PATH`가 사라짐 | ENTRYPOINT를 절대 경로 `/opt/java/openjdk/bin/java`로 (`cfe44c0`) |
| 2 | `could not connect to $PORT=80` | 앱이 `USER 10001`(비root)로 80번을 열려다 실패. 1024 미만은 특권 포트 | 8080으로 이동 시도 (`0debc37`) — **효과 없었음** |
| 3 | 여전히 `$PORT=80` | Vercel이 `PORT` 환경변수를 무시하고 계속 80으로 라우팅 | java 실행 파일에 `cap_net_bind_service` 부여, 80번 복귀 (`2cdd299`) |

**교훈:** Vercel 문서는 "`PORT`로 포트 변경 가능"이라고 하지만 실제로는 80으로
라우팅했습니다. 문서를 믿고 우회하는 대신 **80을 열 수 있게 만드는 쪽**이 맞았습니다.

3번은 로컬에서 특권 포트 제한을 강제로 켠 상태(`net.ipv4.ip_unprivileged_port_start=1024`)
로 검증했습니다. 그냥 되는 환경이라 통과한 게 아니라, 막힌 환경에서 권한 덕에
통과하는 걸 확인했습니다:

```
uid=10001(appuser)
Tomcat started on port 80 (http)
GET /health => 200 {"status":"UP"}
```

로컬에서 이미지를 직접 검증하려면:

```bash
docker build -f Dockerfile.vercel -t t08-check .
docker run -d --name t08 --sysctl net.ipv4.ip_unprivileged_port_start=1024 -e SERVER_PORT=80 -p 18081:80 t08-check
docker logs t08
curl http://localhost:18081/health
docker rm -f t08
```

## 배포 성공 이후 — 남은 과제

`/health`가 `{"status":"UP"}`을 주면 여기부터입니다.

### ⚠️ 순서가 중요합니다

**최종 URL을 확정한 뒤에 패스키를 등록하세요.** 패스키는 RP ID에 묶입니다. 나중에
도메인을 바꾸면(커스텀 도메인, Render 이전 등) 등록한 패스키가 **전부 무효**가 되고
증거를 다시 캡처해야 합니다.

### 실제 기기로 한 번에 처리 (C01·C03·C10·C11·C26·C52)

새 시크릿 창 + 실제 패스키를 쓸 수 있는 기기에서:

1. `/` 가 로그인 없이 열리고 T01 소개 내용이 그대로 보이는지 (C10, C11)
2. `/private` 직접 열면 401로 거절되는지 (C15~C17)
3. `/access` 에서 **합성 이름**으로 첫 패스키 등록 → 비공개 자료 3건 확인
4. 로그아웃 후 같은 패스키로 재로그인
5. 두 번째 패스키 등록 → 첫 번째 삭제 → 남은 것으로 로그인 (C42~C46)
6. **패스키가 실제로 어디 저장됐는지 기록** — 기기 자체 / Google 비밀번호 관리자 /
   보안 키 중 하나 → `docs/T08-SUBMISSION.md`의 "패스키 저장 위치" (C26)
7. 결과물 HTTPS URL을 `docs/T08-SUBMISSION.md`에 기입 (C01, C52)

> 두 번째 패스키에 **첫 번째와 다른 이름**을 쓰세요. 같은 이름은 이제 409로 막히지만
> (`3a951fc`), 굳이 밟을 필요 없습니다.

### 직접 쓰셔야 하는 것 (C53)

`docs/T08-SUBMISSION.md`의 **"AI와 내 판단"** 3줄입니다.

현재 "내가 직접 판단한 일"에 적힌 항목들(비밀번호 없는 공개 등록, 서버 세션, 마지막
패스키 삭제 금지)은 실제로는 **코덱스가 내린 결정**입니다(D-007, D-011 등). 채점자가
커밋 기록과 대조하면 드러납니다. **AI가 대신 쓸 수 없는 유일한 항목**이니 직접
다시 쓰세요.

### 공식 과제 페이지 확인 (D-003)

통과 기준 **C04~C09**가 과제 카드 이미지에 없습니다. 위치상 일반 제출 규칙으로
보이지만 확인 안 된 상태입니다. 공식 페이지에서 확인해서
`docs/T08-ACCEPTANCE-MATRIX.md`를 채우세요. 5분이면 끝나고, 남은 것 중 유일한
"모르는 것"입니다.

### Supabase 무료 플랜 주의

**1주일 미사용 시 프로젝트가 일시정지됩니다.** 제출 후 심사까지 시간이 뜨면 심사자가
열었을 때 DB가 자고 있을 수 있습니다. 제출 후에도 가끔 열어서 깨워두세요.
과제 통과에 직결됩니다.
